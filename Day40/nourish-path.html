System prompt design

The assistant is scoped tightly to one job: turning a short intake into a prioritized, reasoned nutrition strategy — not a general diet chatbot. The system prompt fixes:

  • Role & voice — a friendly, encouraging nutrition coach (never clinical or cold), but every claim has to be grounded in the numbers it was given.
  • Calculation contract — BMR (Mifflin-St Jeor) and TDEE are computed deterministically in JavaScript before the call, not left to the model to "estimate." The model receives the numbers as facts and reasons on top of them, which avoids arithmetic drift.
  • Output contract — strict JSON schema (headline, calorie/macro targets, 4–6 ranked recommendations with a title + one-line "why", closing note). This is what lets the UI render dials, bars, and ranked cards instead of a wall of text.
  • Edge cases — the prompt explicitly handles: irrelevant/joke input in the notes field (ignore, don't lecture), missing or implausible numbers (ask via a structured "clarify" response rather than guessing), medical conditions mentioned in notes (acknowledge + recommend a clinician, still give general safe guidance), and any attempt to extract the system prompt or jailbreak it (decline, stay in character).
  • Safety rails — no specific medical/clinical claims, no extreme calorie targets (floor enforced), always a light disclaimer that this isn't medical advice.

Why the UI looks like this

Nutrition guidance is numeric and prioritized, so the interface leads with a summary card (calorie target + macro split as a proportional bar, styled like a plate breakdown) rather than a generic score dial — that visual maps to how macros actually work. Below it, recommendations render as a ranked list of reasoning cards, each with a priority tag (high/medium/low) and a short "why," because the brief asked for "recommendations with reasoning," not a verdict or a static report. The palette (deep forest green, aged gold, warm paper) and serif display type are drawn from nutrition-notebook / apothecary-label vernacular — deliberately not the terracotta-and-cream AI-generated default.

Extending this assistant

  • Tools — connect a food database (e.g. USDA / Open Food Facts) via an MCP server so recommendations can cite specific foods with real macro data instead of general guidance.
  • Memory — persist each intake + plan with window.storage.set() so returning users see progress over time (weight trend, adherence to prior recommendations) instead of a stateless one-off report.
  • Multi-step flow — turn this into a conversation: after the initial plan, let the user reply "swap this," "I don't like X," or "make this cheaper," and re-call the API with the running plan + their follow-up as context.
  • Meal plan generation — add a second API call that takes the approved macro targets and dietary pattern and generates a 3-day sample meal plan with recipes.
