Day 51/60 — Claude AI Learning Challenge
🎯 Topic: Kicking Off the 10-Day Capstone — "NetVault"

Today marked the start of my 10-day AB Talks capstone project, run as a real Software Development Lifecycle (Requirements → Design → Setup → Implementation → Testing → Deployment → Maintenance) — all inside one continuous Claude conversation acting as my co-founder/product mentor/tech lead.

🔍 What I Did
Went in with no idea at all and let Claude interview me one question at a time to discover the right project
Landed on my own real pain point from work: tracking switches/VLANs/configs in scattered, outdated Excel sheets
Claude pushed back on scope repeatedly given my constraints — total beginner, only 30–60 min/day for 9 remaining days — steering me toward the most impressive-but-finishable project instead of the most ambitious one
Defined the project as NetVault: a local, dashboard-first network inventory & VLAN tracker
📦 Deliverables Generated Today
Product Requirements Document (PRD) — problem statement, goals, in-scope vs. explicitly out-of-scope features, target users, risks & mitigations
9-Day Implementation Blueprint (Days 2–10) — a fully detailed, day-by-day build plan (objectives, what I'll learn, step-by-step instructions, files to create, common bugs, end-of-day checklists) written so a fresh AI chat can pick up any day with zero re-explaining
Pitch Deck — problem, users, solution, key features, technical approach, future scope, and vision
🧠 Key Decision

Chose the simplest possible tech stack on purpose: plain HTML/CSS/JavaScript with browser localStorage as the data store — no server, no database install, no hosting account. For a total-beginner builder with a tight daily time budget, removing setup/deployment risk mattered more than using a "fancier" stack.

💡 What I Learned
How to run a structured product discovery interview instead of jumping straight to building
Why protecting scope is harder — and more valuable — than adding features
How a single well-scoped PRD + blueprint can carry a multi-day build across separate AI conversations without losing context
